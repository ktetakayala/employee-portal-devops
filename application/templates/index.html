Automated CI/CD Pipeline for Employee Portal

A hands-on DevOps project demonstrating automated infrastructure provisioning, containerization, continuous integration and continuous deployment using Terraform, Docker, GitHub Actions, Amazon ECR and AWS EC2.

View Architecture Explore Pipeline

About the Project

The objective of this project is to simulate a real-world DevOps deployment where developers can push application changes to GitHub and automatically deploy the latest version to an AWS EC2 instance.

Infrastructure as Code

AWS infrastructure is provisioned and managed using Terraform, including EC2, networking, security groups, IAM roles, ECR and Elastic IP.

Containerization

The Flask Employee Portal is packaged into a Docker image using Python 3.12 and Gunicorn.

Continuous Integration

GitHub Actions installs application dependencies and executes automated tests before any deployment takes place.

Continuous Deployment

Successful builds are automatically pushed to Amazon ECR and deployed to the EC2 Docker host.

Cloud Architecture

The application follows a simple but practical container-based deployment architecture on AWS.

Security Practices

Security controls were included as part of the deployment design instead of being added later.

AWS OIDC

GitHub Actions authenticates to AWS using temporary OIDC credentials instead of storing long-lived AWS access keys.

Least Privilege IAM

Separate IAM permissions are used for GitHub Actions and EC2, with access limited to the operations required by each component.

Restricted SSH

GitHub runner IP addresses are temporarily allowed on port 22 during deployment and removed after the deployment finishes.

Non-Root Container

The Employee Portal container runs using a dedicated non-root application user.
